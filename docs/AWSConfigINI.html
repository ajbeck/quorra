[AWSConfigINI]

A Swift package for reading, editing, and writing AWS shared-config files (~/.aws/config and ~/.aws/credentials) with parser parity against the AWS Go SDK, fcntl-locked concurrent writes, and a lean Codable layer for the AWS schema.

01Overview

AWSConfigINI is the engine behind Quorra's profile management. It does four things:

  • Parses AWS INI files matching the AWS Go SDK reference parser exactly — including the awkward bits ([default] vs [profile foo] vs [foo], sub-property maps under services, the =-or-: separator, comment-trim asymmetry, BOM detection).
  • Edits documents in memory through a value-typed API (Document, Section, Key) with deterministic key/section ordering on write.
  • Writes atomically with an fcntl advisory lock so the Quorra app and CLI can both touch the same file without losing updates.
  • Maps AWS structures onto Swift via a Codable encoder/decoder plus three opinionated structs (Profile, SSOSession, ServicesEntry).
scopeThis package is AWS-aware on purpose — section-name projection ([profile foo] ↔ [foo]) lives inside the module. It is not a general-purpose INI library.

02Install

The package lives at Packages/QuorraCore and exposes the AWSConfigINI library product. Inside Quorra, depend on it via the local SwiftPM package:

Package.swift swift 
import PackageDescription

let package = Package(
    name: "YourTarget",
    dependencies: [
        .package(path: "./Packages/QuorraCore"),
    ],
    targets: [
        .target(
            name: "YourTarget",
            dependencies: [
                .product(name: "AWSConfigINI", package: "QuorraCore"),
            ]
        ),
    ]
)

Then, in any file:

YourFile.swift swift 
import AWSConfigINI

03Quickstart

  1. Read a file

    Pass the URL explicitly. The flavor (.config or .credentials) tells the AWS overlay how to project profile names.

    read.swift swift 
    let url  = URL(filePath: "~/.aws/config").resolvingSymlinksInPath()
let doc  = try AWSConfigINIDocument(contentsOf: url, flavor: .config)

let region = doc.section("profile dev")?.key("region")?.stringValue
// "us-east-1"

  2. Edit a value

    Section is a value type. Mutations route through Document.update(_:_:) which mutates in place.

    edit.swift swift 
    var doc = try AWSConfigINIDocument(contentsOf: url, flavor: .config)

doc.update("profile dev") { section in
    section.setKey("region", value: "eu-west-1")
    section.setKey("output", value: "json")
}

  3. Save with locking

    Document.update(at:flavor:_:) is the safe entry point. It acquires an fcntl lock around the read-modify-write cycle, atomically replaces the file, and prepends the managed-mode header on first write.

    save.swift swift 
    try AWSConfigINIDocument.update(at: url, flavor: .config) { doc in
    doc.update("profile dev") { s in
        s.setKey("region", value: "eu-west-1")
    }
}

  4. Use a typed model

    The Profile struct decodes a profile section directly. The default snake-case strategy maps Swift camelCase to AWS snake_case (ssoSession ↔ sso_session).

    decode.swift swift 
    let dev = try AWSConfigINIDecoder()
    .decodeProfile(Profile.self, named: "dev", from: doc)

print(dev.region, dev.ssoSession as Any)

04Concepts

The data model is three layers

A parsed INI file becomes an AWSConfigINIDocument, which is an ordered list of Sections, each an ordered list of Keys. Every Key's value is either a plain string or a sub-property map — there's no third case.

~/.aws/config ini 
# default credentials
[default]
region = us-east-1
output = json

# work account
[profile dev]
region             = us-east-1
sso_session        = my-sso
credential_process = /usr/local/bin/quorra-cli credentials --profile dev

[sso-session my-sso]
sso_start_url           = https://example.awsapps.com/start
sso_region              = us-east-1
sso_registration_scopes = sso:account:access

[services my-services]
dynamodb =
  endpoint_url = http://localhost:1234

Profile vs section

Profile names are not the same as section names. AWS encodes the same profile differently in config and credentials:

file flavordefault profilenamed profile
.config[default][profile NAME]
.credentials[default][NAME]

Use document.profileSection(named:) or the encodeProfile / decodeProfile convenience methods to let the projection happen automatically. Or call flavor.profileSectionName(for: name) if you want the raw section name.

Two write paths

There are exactly two ways to persist a document:

  • doc.write(to: url, mode:) — atomic-rename only. Use when nothing else writes the file concurrently.
  • AWSConfigINIDocument.update(at: url, flavor:, mode:, _:) — fcntl advisory lock + atomic rename. Use this between processes (the Quorra app and CLI both call this).
per-processThe fcntl lock serializes between processes but not between threads in the same process. If multiple threads in your app could call update(at:_:) concurrently, wrap with an actor or NSLock.

Managed vs read-only mode

Every write call takes a ManagedMode. In .managed (the default) Quorra owns the file and may canonicalize formatting; in .readOnly any write throws .readOnly(URL) immediately, before any IO. The mode itself is a caller-supplied parameter — this module doesn't store the user's preference (the app/CLI persist that in shared Keychain).

07Key

A name + a value. The value is either a string or a [String: String] sub-property map. Coercion to numeric/Boolean is on demand.

08Codable

Snake-case strategy

The default convertToSnakeCase / convertFromSnakeCase handles AWS field names without any explicit CodingKeys:

swiftini
ssoSessionsso_session
credentialProcesscredential_process
roleArnrole_arn
ssoRegistrationScopessso_registration_scopes

For non-AWS naming, set keyEncodingStrategy = .useDefaultKeys or .custom { ... }.

Section-replace semantics

Encoding a value into a section replaces every key in that section. The section's leadingComments survive; per-key comments inside the section are dropped. Other sections in the document are untouched.

ServicesEntry

The [services NAME] shape is two layers of nesting. ServicesEntry wraps it as a [String: [String: String]]:

ServicesEntry.swift swift 
public struct ServicesEntry: Codable, Sendable, Hashable {
    public var entries: [String: [String: String]]
}

// usage
var decoder = AWSConfigINIDecoder()
decoder.keyDecodingStrategy = .useDefaultKeys
let services = try decoder.decode(
    ServicesEntry.self, from: doc, section: "services my-services"
)
services.entries["dynamodb"]?["endpoint_url"]
// "http://localhost:1234"

10Modes & locking

ManagedMode

Mode.swift swift 
public enum ManagedMode: Sendable, Hashable, Codable {
    case managed     // Quorra owns the file, may canonicalize, prepends header
    case readOnly    // Any write throws .readOnly(URL) before any IO
}

Mode is a parameter on every write call. The user's preference (managed vs. read-only) is stored outside this module — the Quorra app and CLI persist it in shared Keychain and pass the resolved mode in.

The managed-mode header

On the first managed-mode write, a comment is prepended at the top of the file:

~/.aws/config ini 
# Managed by Quorra. Edits made outside Quorra may be reformatted.

[default]
region = "us-east-1"

The header is content data — it lives in Document.leadingComments and round-trips through write→read. Subsequent writes are idempotent (no duplicates). Customize via AWSConfigINIDocumentOptions.managedHeaderText.

fcntl advisory lock

Document.update(at:flavor:_:) opens a sibling <path>.lock file and acquires an exclusive fcntl write lock on it before reading the data file. The lock file is intentionally never cleaned up — it is a coordination point, not a data file.

  • Polling. Acquisition uses F_SETLK with a 50 ms poll loop, defaulting to a 5 s timeout. Throws .lockTimeout(URL) on expiry.
  • Per-process scope. Darwin fcntl locks are per-process. The same process always succeeds F_SETLK against itself — wrap with an in-process lock if you call update(at:_:) from multiple threads.
  • Synchronous. Wrap with Task.detached { ... } if you need to call from a Swift Concurrency executor — Thread.sleep would otherwise block the cooperative scheduler.

Atomic write

Both write(to:) and update(at:_:) use Data.write(to:options:.atomic), which writes to a sibling temp file and renames it over the destination. The temp file is removed on success; readers never see a half-written file.

11Errors

All public throws use Swift 6.2 typed throws against a single error enum:

  • .fileNotFound(URL)The file at URL does not exist. Thrown by init(contentsOf:).
  • .ioError(URL, underlying:)A read or write failed for an OS-level reason. underlying carries the original NSError.
  • .lockTimeout(URL)Could not acquire <url>.lock within the configured timeout (default 5 seconds).
  • .readOnly(URL)A write was attempted with mode == .readOnly. Thrown immediately, before any IO.
  • .decodeError(String)Codable decoding failed — missing required field, type mismatch, nested struct, etc. The message names the offending key.
  • .encodeError(String)A value contains characters that cannot survive a write (an unescaped " or \n) or an unsupported container shape was used.
  • .malformedInput(String)A hard parse failure — rare; the parser is almost entirely silent-tolerant. Used for non-UTF-8 file contents.
typed throwsYou can catch exhaustively over AWSConfigINIError. Soft parser issues (duplicate keys, properties before any section, unrecognized lines) do not throw — they're collected on Section.warnings and Document.globalWarnings for inspection.

Iterate every profile

iterate.swift swift 
let doc = try AWSConfigINIDocument(contentsOf: configURL, flavor: .config)

for section in doc.sections where section.name == "default" || section.name.hasPrefix("profile ") {
    let profileName = section.name == "default"
        ? "default"
        : String(section.name.dropFirst("profile ".count))
    let profile = try AWSConfigINIDecoder().decodeProfile(Profile.self, named: profileName, from: doc)
    print(profileName, profile.region as Any)
}

Read-only inspection (no writes possible)

readonly.swift swift 
let doc = try AWSConfigINIDocument(contentsOf: configURL, flavor: .config)

// later, attempt a write — will throw .readOnly without touching disk
do {
    try doc.write(to: configURL, mode: .readOnly)
} catch AWSConfigINIError.readOnly(let url) {
    print("refused to write to \(url)")
}

13Design notes

Some load-bearing choices worth knowing about, with citations to the parser spec and the AWS Go SDK reference parser:

●Parser parity vs AWS Go SDK ●Canonical writer (D03) ●= separator + "value" quoting (D14, D15) ●[default] first (D16) ●Strict bool grammar (D11) ●fcntl advisory lock (D08) ●Section-replace Codable (D05) ●Caller-supplied mode (D02) ●Lean Codable surface (D10) ●Typed throws (D20)

Parser tolerances, not errors

The parser matches the AWS Go SDK's silent-tolerance behavior (parser spec §11): malformed lines are dropped, duplicate keys overwrite + emit a warning, properties before any section are dropped. Look at Section.warnings and Document.globalWarnings for the diagnostics — they don't bubble up as errors.

Why writes are not byte-exact

The writer is canonical, not faithful. It preserves comments and section/key order, but normalizes alignment, separator spacing, and quoting on every write. This is a deliberate trade-off: byte-exact preservation would require a two-layer trivia AST and an order of magnitude more code. The managed/read-only mode pair gives the user explicit control over whether Quorra reformats their file.

Why the encoder replaces sections wholesale

Codable's natural shape is "serialize value → bytes." Mapping that onto field-level diffs against an existing section requires a secondary diffing engine and adds API surface for marginal gain. Section-replace is simple, predictable, and matches what users expect from JSONEncoder. Per-key comments inside a section are dropped on encode; section-level leadingComments survive.

Why init(contentsOf:) uses untyped throws

Swift 6.2 (Xcode 26) crashes the SIL passes (OSSACompleteLifetime) when typed throws is combined with try Data(contentsOf:) inside an init body. The thrown value is still always an AWSConfigINIError — callers can catch let e as AWSConfigINIError for exhaustive handling.
