- Packages/QuorraCore/Tests/IAMIdentityCenterTests/SessionLockTests.swift:129-133 (SessionLockTests.differentSessionsDontBlockEachOther)

This test claims to prove independent session locks do not block each other, but the two signOut operations are immediate stubbed operations and the measured elapsed time is intentionally unused. A production regression to one global session lock would still run both sign-outs sequentially and almost certainly complete within the one-minute suite limit, so the test would pass while the intended concurrency guarantee is broken.

recommendation:

suggested regression test:
Add a test that starts a gated signOut/refresh for s1, waits until it has entered the locked section, starts signOut for s2, asserts s2 completes within a short deterministic timeout, then releases s1 and awaits completion.

minimum fix scope:
Update SessionLockTests.differentSessionsDontBlockEachOther to include a deterministic blocking stub or test hook and a completion-order assertion.

## medium: MockSleeper waiters can miss an already-started sleep and hang tests

id: fnd_sig-feat-test-suite-ca7e335e57-b_bbb09fa837
category: concurrency
confidence: high
triage: confirmed-bug
status: open
feature: Apple test suite ./ckages/QuorraCore/Tests/IAMIdentityCenterTests/Stubs (feat_test-suite_ca7e335e57)

evidence:
- Packages/QuorraCore/Tests/IAMIdentityCenterTests/Stubs/MockSleeper.swift:28-30 (MockSleeper.sleep(for:))
- Packages/QuorraCore/Tests/IAMIdentityCenterTests/Stubs/MockSleeper.swift:47-49 (MockSleeper.sleep(until:))
- Packages/QuorraCore/Tests/IAMIdentityCenterTests/Stubs/MockSleeper.swift:56-59 (MockSleeper.waitForNextSleep())

The helper only resumes continuations that are already registered at the exact moment sleep(for:) or sleep(until:) runs. If a background task reaches and completes the mock sleep before the test task calls waitForNextSleep(), the later continuation is appended with no future sleep guaranteed to resume it. That turns a scheduler ordering race into a permanent test hang rather than a deterministic synchronization point.

recommendation:
Replace the bare continuation list with generation-based waiting, such as a monotonically increasing sleepSequence and a waitForSleep(after:) or waitForSleepCount(atLeast:) helper. Tests should capture the current sequence before starting the producer task or wait for a minimum count, so late registration cannot lose the signal.

test analysis:
The existing helper is itself used as the synchronization primitive, so a missed wakeup manifests as a timeout or hang. There is no dedicated meta-test covering the late-waiter path.

suggested regression test:
Add a test that performs a sleep before registering a waiter and verifies a new generation/count-based API can observe the completed sleep or fail fast instead of suspending indefinitely.

minimum fix scope:
Packages/QuorraCore/Tests/IAMIdentityCenterTests/Stubs/MockSleeper.swift plus call sites that use waitForNextSleep() as a background-task synchronization point.

repro:
Start a task that calls MockSleeper.sleep(for:), allow it to run before the test awaits waitForNextSleep(), then await waitForNextSleep(); no continuation is resumed unless another sleep happens.
